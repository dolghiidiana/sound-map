Sound Map: from movement to sound

A writer describes a scene, hears one proposed arrangement, reshapes it and saves a creative reference. The cafe proves the loop with three recordings; it is not the limit of the broader idea.

Two different jobs

The external AI proposes an initial arrangement. Ordinary browser code responds immediately to dragging. Node is the local go-between for AI requests; saved blueprints stay in browser localStorage.

1 · Move
SceneView receives a drag or arrow key.

2 · Translate
Position becomes stereo pan and prominence.

3 · Hear
The audio engine smoothly updates one layer.

A three-stop reference route

This is a reference route, not a claim that an interactive code tour was completed.

  1. src/components/SceneView.jsx → move: bounds the position, updates the audio engine and records the new state.
  2. shared/mapping.js → soundParameters: horizontal position sets pan; radius reduces prominence. Cleaning has its approved extra outer reduction.
  3. src/audio/audioEngine.js → setPosition / applyPosition / smooth: changes gain and pan on the existing layer rather than starting it again. No AI request is involved.

To change this, start here

  • Sweeping frequency: shared/catalogue.js, Cleaning's gapSeconds: 14. Together with the clip and lead-in, its cycle is about 24 seconds.
  • Loop preparation: src/audio/audioEngine.js → prepareLoop.
  • Reflection adoption: src/components/ReflectionPanel.jsx; suggestion stays separate until Use suggestion.
  • Saved scenes: src/lib/blueprintStore.js; browser-local persistence.
  • Readability: src/styles.css. Recording provenance: AUDIO_CREDITS.md.

A practice to reuse

“Sweeping feels repetitive” became one small adjustable property: the quiet gap. Only that value changed; existing loop tests checked mechanics, then listening established whether it felt better. See tests/mapping.test.mjs and devpost/slice-5-verification.md. For another creative idea, isolate one observable behavior, change one thing and pair technical checks with human judgment.

The build already included this small-change activity and listening comparison. This page recaps that evidence; it does not claim learning mastery or a completed guided code tour.
